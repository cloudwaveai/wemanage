# 运维手册

## 日常

- **看健康**：管理后台"总览"看账号健康汇总与未处理告警。飞书会推送账号级告警（限额、需重新登录、疑似降智、出口 IP 变更）。
- **加/停员工**：员工由飞书通讯录每小时自动同步；飞书离职后其 Key 自动失效。手动停用见"员工"页。
- **加账号 / 换绑**：见 [deploy.md](deploy.md)。换绑、换 IP 组都会写审计。
- **账号和人的对应**：一个账号最多几人共用由"设置 → 一个账号最多几人共用"决定（默认 3）；一个人也可以有多个账号。在"账号"页的"使用人"一栏点"+ 添加"加人、点名字旁的 × 移除。一个人有多个账号时，网关按请求挑账号：同一段对话固定用同一个账号（提示词缓存和 WebSocket 都在那个账号上）；新对话用额度剩得多的那个；某个账号额度用完，网关把这次请求直接转给另一个账号重发（HTTP），WebSocket 连接则让 Codex 自动重连后换账号，员工不用做什么。共用一个账号的人共享它的额度和并发。
- **限定模型**：在"账号"页点"模型"，能看到这个账号有哪些模型、近 7 天各用了多少次；选"只允许勾选的模型"后，这个账号的使用人只能用勾选的（比如不让只拿 Astra 干日常活的人用 Astra），其他模型会被拦下并提示可用的模型（`model_not_allowed`），Codex 里输入 /model 换模型即可；之后新出的模型默认不开放。一个人有多个账号时，请求会自动走允许该模型的那个账号。
- **第三方客户端**：OpenCode、Command Code 等工具走同样的 OpenAI Responses 接口（`/v1/responses`），Claude Code 等 Anthropic 格式的工具走 `/v1/messages`（Key 放在 `x-api-key` 或 `Authorization: Bearer` 都认），网关会用账号的设备信息补齐 Codex 的请求头。默认只放行官方 Codex；在"账号 → 编辑"里勾选"允许第三方客户端"后，这个账号的使用人就能用，生成 Key 的弹窗里会给出 Claude Code / OpenCode / Command Code 的现成配置。"设置"里的"所有账号都允许非 Codex 客户端"是总开关，一般不开。请求特征和官方 Codex 不同，账号被风控的可能更大，只给确有需要的账号打开。
- **添加账号**："账号 → 添加账号 → 登录账号"里选账号类型：ChatGPT、Kimi Code（国内 / 国际版）、Antigravity（Google）、Grok（xAI）、Meta Muse、Devin，都是 CPA 支持的登录（Claude 按公司规定不接）。ChatGPT、Antigravity、Devin 是跳转登录：复制登录链接到浏览器登录，登录后跳到的 localhost / 127.0.0.1 页面打不开是正常的，把地址栏完整地址粘回来（ChatGPT 30 分钟内有效，其它 5 分钟）。ChatGPT 的登录由网关自己按官方 Codex 的方式做（回调 `http://127.0.0.1:1455/auth/callback`），换到凭证后写进 CPA：CPA 的登录链接还是旧的 localhost 回调，2026-10 起在 OpenAI 的密码页报 Route Error 400。同一个 ChatGPT 账号再登录一次只会刷新凭证，不会多出一个账号；Kimi、Grok、Meta 是授权码登录：打开链接授权后点"我已授权，完成"，网关等 CPA 自己拿到凭证。只有 ChatGPT 和 Kimi Code 有 5 小时 / 每周额度显示；生图、联网搜索、WebSocket 只给 ChatGPT 账号。员工用 Codex 时网关把 Responses 请求经 CPA 翻译给各家，模型列表在"账号 → 模型"里看。
- **订阅续费**："账号"页的"订阅"一栏是 ChatGPT 账号的下次续费日（`10/29 续费 · 还有 21 天`）；账号设了取消订阅时显示"到期 · 不再续费"（一周内变橙色），扣款失败显示"欠费"。数据来自 ChatGPT 的 accounts/check（和额度一样经 CPA 用账号自己的令牌和出口查），每 6 小时查一次，点"刷新额度"时也会顺带查；新加的账号加完马上查。查询失败时先用登录凭证里的"本期到期日"顶上，并标"未能核实"，鼠标悬停能看到原因。
- **移除账号**："账号 → 编辑 → 移除账号"，确认后从网关和 CPA 里删掉这个账号，腾出它在 IP 组里的名额；使用人随之失去这个账号（有别的账号的自动用别的），历史用量记录保留。上游账号本身不受影响，想加回来重新登录添加即可。只想换出口 IP 的话不用移除，在编辑里直接换 IP 组。
- **服务账号**：给公司自己的平台用（例如国内的 New API 把 gpt-6-luna 接成一个渠道），不对应飞书里的人。在"员工"页点"新建服务账号"，创建后 Key 只显示一次；之后在"Key 前缀"一栏可以重置。服务账号不用确认设备、不受公司网络限制，没有周报和额度提醒，飞书同步也不会停用它。给它分配账号的方式和员工一样（"账号"页"使用人"里加），分配的账号要打开"允许第三方客户端"。平台那边的渠道：类型 OpenAI，Base URL `https://ai.cloudwaveai.cn`，Key 填服务账号的 Key。
- **看团队**：部门负责人在"团队"里看本部门的总请求量和 token，以及每个成员的账号状态（正常 / 限额中及恢复时间 / 需重新登录 / 还没开通），方便帮成员处理；不显示个人用量、排名和活跃时间。超级管理员看全部。
- **工作看板**：超级管理员在"工作看板"里看每个人的 Token 用量（今天 / 昨天 / 近 7 天 / 近 30 天：输入、输出、请求、会话、常用模型、最近使用，以及每天的总量），和 AI 整理的**每日工作总结**：每人当天做了哪些事、进展到哪、有没有卡住，加一段团队概览。总结每天 01:30 根据前一天的对话自动生成，也可以在看板上选某一天点"生成 / 重新生成"（选今天就是截至现在）。用哪个账号、哪个模型写总结在"设置 → 每日工作总结"里选（不选就不生成），请求经 CPA 用这个账号的令牌、出口和设备信息发出，会用掉它一些额度：每天每个有对话的人一次，再加一次团队概览。送给模型的只是员工自己打的消息（去掉 Codex 自动附带的环境、AGENTS.md 等上下文，去重，每条截短，每人每天约 1.6 万字以内）和每个会话最后一次回复的开头。总结和对话原文一样按"原文保留天数"清理。
- **看对话记录**：超级管理员在"对话记录"里可以看任何人的原文，每次查看都写审计。员工只有自己的"使用日志"（时间、模型、状态、Token、耗时），看不到原文；部门负责人看不到成员的对话。
- **看风险**：管理后台"风险中心"看防 Key 外泄的事件；高风险事件和自动冻结会实时推送飞书。处理方法见下文"风险中心与冻结"。

## 账号状态含义

| 状态 | 处理 |
|---|---|
| 正常 | 无需处理 |
| 限额中 | 账号命中 5 小时/每周额度，到显示的恢复时间自动恢复 |
| 需重新登录 | 上游 token 失效：到"账号"页对该账号重新走一次 OAuth 登录 |
| 疑似降智 | 响应模型与请求不符，或推理量被封顶。考虑降低该账号并发、检查出口 IP，必要时联系 OpenAI |
| 已停用 | 管理员手动停用 |

## 风险中心与冻结

网关会登记每个 Key 用过的设备和网络，用来发现 Key 被分享或转卖。规则和阈值见设计文档 [`superpowers/specs/2026-09-28-key-sharing-risk-design.md`](superpowers/specs/2026-09-28-key-sharing-risk-design.md)，模式和阈值在"设置 → 风险控制"里调。

**数据面拒绝请求时返回什么：** 每种拒绝都带一句给员工看的中文说明（原因 + 下一步）。拒绝的请求也记进日志，`error_type` 就是下面的错误码，员工在"使用日志"里能看到对应的中文原因。

| 错误码 | 含义 | 谁来处理 |
|---|---|---|
| `client_not_allowed` | 不是官方 Codex 客户端，而员工的账号都没开放第三方客户端（或开启了"要求安装 ID"而请求没带）。命令行、VS Code 插件和 Codex 桌面版都算官方客户端（按 User-Agent / Originator 以 codex 开头识别，不分大小写） | 员工改用 Codex；确需 OpenCode、Command Code 等工具时，在"账号 → 编辑"里给这个账号打开"允许第三方客户端" |
| `model_not_allowed` | 请求的模型不在员工任何一个账号的可用模型里 | 员工在 Codex 里输入 /model 换模型；确需这个模型时，在"账号 → 模型"里放开 |
| `device_unconfirmed` | 设备待确认且已过确认期限，或严格模式下的新设备 | 员工到"我的设备"确认 |
| `device_blocked` | 设备被拉黑 | 管理员核实后"解除拉黑"，员工再确认 |
| `account_frozen` | 员工被冻结 | 管理员核实后解冻 |
| `key_revoked` | 用的是已经重置掉的旧 Key（记在原主人名下，所以使用日志里能看到） | 员工用新 Key 重新配置 |
| `invalid_key` | Key 不存在（不知道是谁的，不记日志） | 员工检查配置 |
| `no_account_bound` | 员工有 Key 但没绑定账号 | 管理员绑定账号。网关每人每天最多提醒一次超级管理员；绑定后员工会收到飞书通知 |
| `account_needs_login` | 账号登录失效 | 管理员重新登录该账号 |
| `account_rate_limited` | 账号额度用完（5 小时或每周窗口） | 等恢复；返回里带恢复时间 |
| `network_not_allowed` | 开了"只允许公司网络"，请求来自外网 | 员工回公司网络，或管理员给该员工开远程使用 |
| `content_blocked` | 触发内容审核（拦截模式） | 管理员核实是否误判 |

**给 Codex 的返回形状（有意为之）：** Codex 对一般的 4xx 会先重试 5 次（WebSocket 失败后还会改走 HTTP 再试 5 次），十几秒后才显示错误；只有 `invalid_prompt` 错误会直接显示 message、不重试。所以对 Codex 客户端，上表中"需要人处理"的拒绝一律以 HTTP 400、`code: invalid_prompt` 返回，网关自己的错误码放在 `reason` 字段里，日志记的也是这个错误码。其它客户端照常收到原状态码（401/403 等）和原错误码。

额度用完时按 Codex 自己的 `usage_limit_reached` 格式返回（429，带 `resets_at`）：Codex 会立即停下并显示"Try again at …"。上游的 429 如果是额度用完（或要等一分钟以上），网关也会改写成这个格式，并去掉上游返回里的 `plan_type`，否则 Codex 会提示员工"升级 Pro / 购买额度"。只等几秒的短暂 429 原样返回，让 Codex 自动重试。

**联网搜索：** luna 这类模型用 Codex 的独立搜索工具（web.run），它请求 `{base_url}/alpha/search`。CPA 不转发这个接口，由网关代为调用：用员工绑定账号的凭证，经 CPA 管理接口 `api-call` 请求 `chatgpt.com/backend-api/codex/alpha/search`（走该账号的出口代理）。日志里类型记为"联网搜索"，内容只记搜索词和结果条数、来源网址。员工的 Codex 配置里要有 `supports_standalone_web_search = true` 和那个请求头（生成 Key 时给出的安装命令和手动配置都有）；用 CC Switch 原样导入的配置没有，模型只能在终端里 curl。

**一条命令安装：** 员工在门户生成的安装命令只带一个 10 分钟内有效、只能用一次的安装码（存在网关内存里，重启后作废，重新生成即可），脚本从 `/i/<码>` 下载。脚本备份并改写员工电脑上的 `~/.codex/config.toml`，Key 写在 `experimental_bearer_token` 里，文件权限设为 600。

**状态 499（没回答完就断了）：** WebSocket 对话里，一轮回答还没结束连接就断了，这一条记为 499，`error_type` 写明是谁先断的：`client_closed`（Codex 断开，常见于员工按 Esc、打断或关掉 Codex）、`upstream_closed`（上游断开）、`gateway_restart`（网关重启，Codex 会自动重连）。更早的记录只写 `websocket_closed`，分不出是谁。

**日志多久能看到：** 网关每秒把新请求批量写一次库，一条请求结束后一两秒就能查到（流式对话要等整轮回答结束才记录）。"对话记录 / 使用日志"页每 10 秒自动刷新，"我的用量"每 30 秒；账号额度在有请求时最多每分钟更新一次，空闲的账号每 5 分钟检查一次、快照超过 30 分钟才去官方接口重新查。

**员工的额度提醒：** 默认开，员工可以在"我的用量"里关掉。网关每 2 分钟看一次员工账号的最新额度快照：某个窗口（5 小时 / 每周）用到 80% 时提醒一次，用完时再提醒一次，都写明恢复时间，只发给员工本人。只有"用完"那条会提到剩余重置卡。没配飞书时不发。

**重置卡：** ChatGPT 账号可能有 OpenAI 发放的重置卡（`wham/rate-limit-reset-credits`）。员工在"我的用量"里能看到张数并使用；网关经 CPA `api-call` 用该账号凭证调用 `…/consume`（优先用最早过期的一张），成功后立即解除网关上的限流标记并刷新额度。员工有可用重置卡时即可使用，前端确认弹窗会提示"用一张少一张"。每次使用记审计 `reset_credit_use`。

**员工被自动冻结时怎么处理：**

1. 打开"风险中心"，点员工名进入详情，看触发的规则、涉及的设备和网络（IP、归属地、运营商、是否机房）。
2. 联系员工核实：这些设备是不是他的？当时是否在用代理 / VPN？
3. **确认是误判**（例如员工的代理自动切换节点）：把他本人的设备"信任"，点"解冻"，并提醒他把网关域名设为直连。
4. **确认是分享或转卖**：把陌生设备"拉黑"，让员工重新生成 Key（旧 Key 作废），再解冻；是否追究按公司制度处理。审计里有完整的操作记录。
5. 在"风险中心"把相关事件标记为已处理。

解冻会清掉该员工在内存里的"最近使用"记录，所以不会因为冻结前的旧记录马上又被冻结；如果外人还拿着有效 Key 继续用，会再次触发。

**有意识的限制**：如果员工在自己电脑上架中转，把别人的请求伪装成自己的 Codex 发出，设备和 IP 都是他本人的，设备规则识别不出来。这种情况只能靠全量日志留痕和公司制度约束。

**IP 归属地库（可选）**：下载 [ip2region](https://github.com/lionsoul2014/ip2region) 的 IPv4 `.xdb` 数据文件，放到 `deploy/geoip/ip2region.xdb`，在 `.env` 里设 `GEOIP_DB=/data/geoip/ip2region.xdb` 后重启 gateway。启动日志出现 `geoip enabled` 即生效；加载失败会打印 `geoip disabled` 并跳过归属地判断，其它规则不受影响。建议每季度更新一次数据文件。

**取真实 IP 的前提**：网关只信任来自内网地址（即 Caddy 容器）的 `X-Forwarded-For`，取最右边一个。不要把 gateway 的 8080 端口直接暴露到公网；如果前面还有 CDN，要在 Caddy 里配置 `trusted_proxies`，否则看到的会是 CDN 的 IP。

## 公司网络限制

"设置 → 公司网络限制"打开后，员工的 Key 只能从填写的公司出口 IP 使用，泄露出去的 Key 在公司外是用不了的。

- **怎么查公司出口 IP**：在公司每条宽带（电信、联通、移动各测一次）上打开 `https://api.ipify.org`，把看到的 IP 都填进去；整段 IP 可以写成 `203.0.113.0/24` 这样的网段。出口 IP 变了要及时更新，否则全公司都会被拦。
- **需要在外办公的人**：在"风险中心 → 员工详情"里打开"允许在公司网络外使用"。这些人仍然受设备登记和异地同时使用检测的约束。
- 被拦截的请求返回 `network_not_allowed`，风险中心记一条"公司网络外使用"，员工每天最多收到一次飞书提醒。
- 状态变化大约 3 秒内生效。

## 内容审核

请求发给 OpenAI 之前，网关会用"设置 → 内容审核"里的规则检查员工最新的一条消息（不看历史上下文和工具输出）。默认规则针对 OpenAI 会直接封号的网络滥用：勒索软件、盗号/键盘记录、免杀、僵尸网络/DDoS、编写木马后门、钓鱼套件、武器化漏洞利用。

- **仅提醒**（默认）：请求照常放行，风险中心记一条"触发内容审核"（带规则名和前后约 40 个字的片段），同一员工同一规则一小时内只提醒管理员一次。
- **拦截**：直接返回 `content_blocked`，同样记事件、提醒管理员。
- 建议先用"仅提醒"跑一段时间，看命中是否都合理，再决定是否改成拦截。规则是不区分大小写的正则，可以在设置页增删。

## WebSocket 连接

默认与官方 Codex 一致走 WebSocket：员工 Codex ⇄ 网关 ⇄ CPA ⇄ OpenAI 都是长连接，一条连接上按轮次收发请求。网关对每一轮照常做并发限制、风控、内容审核和记日志；带 `previous_response_id` 的增量轮次，日志里只记这一轮新增的内容（完整上下文可以在同一会话的前几轮里看到）。额度信息从 `codex.rate_limits` 事件记录。

- **临时关闭**：设置 → 基础 →「关闭 WebSocket」。之后新的握手返回 426，员工的 Codex 会自动退回 HTTP，不用改任何配置。
- **非 ChatGPT 账号**（如 Kimi 试用）始终走 HTTP。
- 网关重启时会主动关闭所有长连接，Codex 会自动重连。

## 更换出口 IP

到"IP 组"改代理地址。注意：**更换出口 IP 本身是风控信号**，非必要不换；每次更换都记审计。系统每 30 分钟自检各组实际出口 IP，代理商偷偷换 IP 会告警。

代理地址支持 `socks5://`、`socks5h://`、`http://`、`https://`，也可以填 `direct`：不走代理，直接用网关服务器自己的 IP 出去。`direct` 适合 Kimi 试跑；正式的 ChatGPT 账号建议每 5～10 个配一个固定的住宅或静态 IP 代理。

## 备份与恢复

**要备份的**：PostgreSQL 数据库与 CPA 凭证目录（`deploy/cpa/auths`，含各账号 OAuth token）。

生产的数据库在阿里云主机上（海外网关服务器通过 `DATABASE_URL` 远程连接），所以**数据库备份在阿里云本机做**：本地 `pg_dump` 走 loopback，几秒到几分钟完成，不占海外小盘，备份文件留在阿里云 `~/gateway-backups/`（每天 04:20 定时，默认保留最近 1 份自动备份，脚本 `deploy/aliyun/backup.sh`，密码在阿里云 `~/.gateway-backup.env`）。备份写入临时文件，校验成功后才转为正式备份并轮换旧文件；更新前的手动备份不受自动轮换影响。

```bash
# 阿里云主机上：手动立即备份（定时任务已装好，一般不用手动跑）
~/gateway-backups/backup.sh

# CPA 凭证（在海外服务器的 deploy 目录里）
tar czf auths-$(date +%F).tgz -C deploy/cpa auths
```

建议再每天把阿里云的备份上传到对象存储，异地留存。

**恢复**：拿到阿里云上的 `gateway-*.sql.gz` 后，在能连到数据库的机器上 `gunzip -c gateway-xxx.sql.gz | psql "<DATABASE_URL>"`；CPA 凭证解压回 `deploy/cpa/auths` 后 `docker compose up -d`。

## 数据保留

- 对话原文（片段）超过设置里的保留天数（默认 180）自动删除，每天 03:30 执行。
- 用量统计、周报、审计永久保留。
- 日志写库失败会先落到 `gateway_spool` 卷的 `pending.jsonl`，数据库恢复后自动回放；若该文件持续增长，说明数据库有问题，需排查。
- 数据库拒收的记录（数据本身有问题，重试也没用）会放进同一个卷的 `rejected.jsonl`，每行带着拒收原因。这个文件正常应为空；出现内容时看网关日志里的 `record rejected by the database`，修复原因后可以把记录挪回 `pending.jsonl` 让它重新补录。

## 周报

每周日 16:00（北京时间），为本周用过网关的员工各自动编写一份本周周报草稿（第一人称、按事项分条，员工复制后稍作修改就能提交），通过飞书只发给员工本人，部门负责人和其他人都看不到。草稿只根据本周的对话整理，不含使用时段，不评价工作量，也不编造下周计划。用的是 `.env` 里配置的独立 OpenAI 兼容端点的小模型，**不消耗员工订阅**。员工可以在"我的周报"里自己关掉（关掉后不再生成也不推送）；管理员可在"设置 → 周报"里整体关闭。

## 简报

超级管理员在「简报」页手动选择起止日期（包含两端，最多 31 天），也可快捷选择昨天、近 7 天、本周或上周。点击「生成简报」后，系统先补齐所选日期缺失、失败或不完整的每日工作总结，再按当前提示词生成团队简报；包含今天时按生成时已有记录整理。任务在后台运行，页面自动显示进度和结果。没有工作内容时会明确提示，不会编造简报。不同日期范围分别留存历史，同一范围重新生成会替换上次结果。

每位管理员都有自己的提示词和自动推送开关，其他管理员看不到其设置和简报。保存设置后，每周五 10:00（北京时间）仍可自动汇总本周一至周四的工作并推送到本人飞书，手动选择日期不会改变自动推送的周期。写简报使用「设置 → 每日工作总结」中选定的账号和模型，会消耗该账号额度。

「生成并发送到飞书」使用选定日期和当前提示词生成并推送；非空提示词也会保存。没有配置飞书时，定时任务只生成并保存；手动仍可点击「生成简报」在页面查看。飞书发送失败时保留已生成的正文并显示错误。简报随每日工作总结的保留期限清理。

## 调整并发 / 超时

"设置"页可改默认并发（1–32）、排队超时（1–600 秒）、保留天数、Codex 版本模板、脱敏规则、客户端识别规则、管理员名单。也可对单个账号单独设并发上限。

## 排障

- **员工报 502**：CPA 不可达，`docker compose logs cpa`。
- **员工报 503 account_needs_login**：该账号 token 失效，重新登录。
- **额度不显示**：「账号」页的 5 小时 / 每周额度有两个来源。
  - 有请求时：从响应头和 WebSocket 的 `codex.rate_limits` 事件里记录，需要 CPA 开着 `passthrough-headers: true`。
  - 闲置时：网关每 5 分钟检查一次，对超过 30 分钟没更新的 ChatGPT / Kimi 账号，经 CPA 的 `api-call` 用该账号自己的令牌和出口查一次官方接口：ChatGPT 查 `chatgpt.com/backend-api/wham/usage`（和 Codex `/status` 同一个接口），Kimi 查 `api.kimi.com/coding/v1/usages`（和 kimi-cli `/usage` 同一个接口）。
  - 也可以点账号行里的「刷新额度」手动查一次，每个账号每分钟最多一次。
  - 查询失败会记在网关日志里，搜 `quota probe` / `quota refresh`。
  - 5 小时和每周按窗口长度区分，不按上游字段的先后位置。Pro 账号有时只报一个每周窗口。
- **看 CPA 明细**：临时把 `cpa/config.yaml` 的 `request-log` 设为 true 并重启 cpa（排障后记得关掉，避免重复留存明文）。

- **工作数据与应用 API 渠道**：项目归属、复盘口径、隐私边界、保留策略和渠道接入见 [工作数据说明](work-data-current-state.md)。
