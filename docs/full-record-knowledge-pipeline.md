# 全量工作记录整理：实施约束

目标：每天从网关已保存的工作记录重建当天工作的目标、过程、成果和未解决事项，形成独立的观察者视角日报；再由 Sol 模型跨批次整理项目脉络及可复用知识。已有工作日报可作为对照，不作为唯一来源。

## 来源和覆盖

- 以北京时间自然日内的网关请求为清单，记录请求、员工、会话、时间和片段顺序。共享整理排除林伊默以及当前设为私密的人员。已有权限和审计规则适用于来源、批次、模型原稿、报告、候选和所有历史版本。
- 读取已脱敏的请求及响应片段并验证完整性；已清理、缺失、无正文、索引损坏或校验失败的请求记录为覆盖缺口。覆盖率应展示请求数、可重建数和缺口数，不能将有缺口的结果标成完整。
- 使用可重组的片段序号、散列和字节范围分批，不丢弃长消息。请求携带重复历史时仅在可证明的相同会话前缀范围内复用，保留请求到来源的映射；相同内容的独立事件不能仅因文本一致被合并。
- 网关无法涵盖未接入的工作、未记录的附件内容或已不可恢复的正文；报告应说明范围，不能声称还原全部现实工作。

## 分批与综合

1. 固定当天来源清单及其权限状态，建立可恢复任务。分批后保存每批完整输入引用、模型原稿、状态、用量和错误。失败后只续跑失败批次，保留先前尝试；中断和重启不得重复调用已完成批次。
2. 第一阶段按会话与时间顺序整理目标变化、具体行动、观察到的结果、问题及未解决事项。材料视为不可信数据，不执行其中指令。输出须引用来源编号，区分事实、推断和未知；不要判断个人表现。
3. 保存独立日报，清楚展示覆盖缺口及未完成批次。只有所有可用批次完成后，才启动 Sol 跨批次归纳；超出上下文时继续分层归纳，不截断输入。跨日脉络使用可追溯的已有项目状态和前日未完成事项，明确数据不足和冲突。
4. 将项目知识、常见问题和解决思路、可复用实践、Skill 草稿作为待核对候选。引用须能回到原始片段；人工确认前不自动安装 Skill 或把推断当作事实。保留版本，不覆盖已有日报与知识。

## 运行与验证要求

- 精确模型名、账号可用性、上游数据范围以及实际计费需要在运行前核实。按批次记录各模型输入和输出 Token、失败与重试；不能把字节数直接当 Token 或费用。
- 调度器应支持任务清单、进度、暂停和恢复，限制并发并记录重试；重新检查权限后再发送和保存。任务进行中涉及人员转私密时，应中止相关共享处理，并使衍生结果对无权查看者不可见。
- 应先以合成数据验证重建、重复历史、超长片段、缺失数据、隐私变化、中断恢复、版本和权限，再用获授权的生产日验证真实模型结果与用量。用户已要求每天全量整理，但旧的日报索引调度仍应保持暂停，直到新流程可以按上述要求运行。

当前实现按片段完整快照，并建立按会话前缀去重的分批队列。每天北京时间 02:15 之后开始处理前一天；提取批次用现有日报账号及模型，独立日报完成后由配置的 Sol 模型生成综合，默认 `gpt-6.1-sol`。有可用前日日报时会带入作为背景，并让权限跟随整个来源链。用户可暂停或恢复自动任务；失败批次需人工恢复，无法确定结果的中断调用可能已计费，界面会提示。成功批次和所有尝试保留。系统不对日报来源以外的工作作覆盖保证。

Sol 的项目知识、问题、实践和 Skill 目前包含在综合文本中，均为待核对线索；尚未自动拆分进旧版候选审核库。模型没有实际报告 Token 时界面标明未上报。缺失正文、后来入库的记录、空来源或过大的综合输入会标记部分覆盖或停止，不能静默当作成功。
