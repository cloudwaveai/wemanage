# We-Manage 工作与经验

We-Manage 是独立进程，入口为网关同域名的 `/wemanager/`。网关的 Caddy 通过仅供容器网络访问的 SSH 本地转发连接阿里云的 `127.0.0.1:19081`，不向公网开放分析服务端口。浏览器沿用网关登录；服务逐次校验有效会话、超级管理员身份和修改操作的 CSRF 令牌。

## 第一版范围

- 项目列表和人工填写的项目记录来自网关原有数据；依据人员、案例作者、最后修改人和反馈作者的当前隐私策略过滤。林伊默的私密正文不会向其他管理员展示。
- 项目调用分析统计近 30 天已归属该项目的网关请求，按北京时间的日期和请求模型分组。输入和输出 Token 相加；没有经过网关或没有归属项目的工作不在统计中。
- 从可访问的项目记录整理案例：背景、方法和结果由管理员填写，保存为草稿，人工确认后可以登记复用反馈。修改后回到草稿；原案例版本和历史反馈保留。系统不自动推断个人表现，不自动调用模型或使用重置卡。
- 覆盖提示显示近 30 天网关请求和保有可检索文本的请求；它不是全部工作，也不是绩效指标。费用估算及其未定价边界仍以网关项目与用量页面为准。

## 数据与运行

`wm_cases`、`wm_case_revisions`、`wm_feedback` 在原有网关数据库中独立存放，引用现有项目、事件和员工；服务只新增这些表，不修改原始请求或记录。通过 `wemanage install` 初始化表结构，应用监听 `127.0.0.1:19081`。阿里云当前无 systemd linger，用户级 cron 使用 `flock` 负责开机启动及故障重启，保留既有备份任务；数据库凭证从服务器上既有的环境文件读取，不存入仓库。

访问控制测试应覆盖：未登录和普通用户拒绝访问、CSRF、来源和作者私密规则、修改后重新确认、历史保留以及隐私设置变更后的过滤。添加新数据源或字段时，须在源、分析结果、反馈及历史版本各层执行同等权限约束。

## 日志分析与提取

在「日志分析与提取」按关键词搜索并选择一条可访问的网关日志，确认后使用网关「设置 → 每日工作总结」配置的账号和模型生成清洗草稿、知识候选与 Skill 草稿。模型调用会消耗相应账号额度；不会自动批量调用。发送到模型的是保存的脱敏请求和响应片段；服务检查所有引用的片段都能读取。大于 350,000 字节的记录及缺失片段的记录会拒绝分析，不会静默截断。来源是网关保存的数据，不保证涵盖网关外工作或此前未采集的内容。

每条候选显示来源日志及引用是否与原文匹配；无法匹配不等于虚假，需人工核查。管理员可修改并确认知识或 Skill，或排除候选。模型原文、人工确认版和来源均保留；Skill 不会自动安装或执行。结果仍受原日志所有者、生成者和审核者的隐私限制。当前按单条日志分析，尚无批处理、自动聚类或跨项目综合研究。
