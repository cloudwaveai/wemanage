# 员工使用指南

## 一、拿到你的 Key

1. 打开公司发的网关地址（形如 `https://ai.example.com/`），用**飞书扫码登录**。
2. 首次登录会看到一条使用说明：你在这里的请求和回复会被公司记录，用于用量管理和工作分析，原文保留 180 天；为保障账号安全，还会记录你使用的设备和来源 IP。阅读后点击"我已知晓"。说明内容更新后，需要重新确认一次才能继续使用。
3. 进入"我的 Key"，点击生成。**Key 只完整显示这一次，请立即复制保存**。之后页面只显示打码版本；忘了可以自己重置（旧 Key 立即失效）。

## 二、配置 Codex（推荐）

### 用 CC Switch 一键导入（最简单）

1. 装好 [CC Switch](https://github.com/farion1231/cc-switch/releases/latest)。
2. 两种导入方式：
   - 在「我的 Key」生成 Key 后，直接点弹窗里的「一键导入 CC Switch」；
   - 或者到「一键配置」页，粘贴 Key、选好模型，点「导入到 CC Switch」。
3. CC Switch 会弹窗确认，点「导入」后 Codex 立即切到公司网关。之后直接运行 `codex` 即可。

Key 只写进你电脑上的 CC Switch，不会再发回服务器。CC Switch 导入的配置走普通 HTTP，使用上没有区别。ChatGPT 账号想和官方客户端一样走 WebSocket，可以在 CC Switch 里编辑这个供应商，在 `[model_providers.custom]` 下加一行 `supports_websockets = true`。

### 手动配置

在"一键配置"里复制 Codex 配置片段，写入 `~/.codex/config.toml`：

```toml
model_provider = "company"
model = "gpt-5.1-codex"

[model_providers.company]
name = "Company Gateway"
base_url = "https://ai.example.com/v1"
wire_api = "responses"
env_key = "AISEAT_API_KEY"
requires_openai_auth = false
supports_websockets = true
```

最后一行让 Codex 用 WebSocket 连网关，和官方 Codex 连 OpenAI 的方式一致。以「一键配置」页给出的为准：公司临时关闭 WebSocket、或你的账号不是 ChatGPT 时，那里会写成 `false`；就算没改，网关也会让 Codex 自动退回普通 HTTP，不影响使用。

然后设置环境变量 `AISEAT_API_KEY` 为你的 `sk-emp-...` Key（配置里的 `env_key` 就是告诉 Codex 从这个变量读 Key；没有它 Codex 不会带上 Key，网关会返回 401）。建议写进 `~/.zshrc` 或 `~/.bashrc`：

```bash
export AISEAT_API_KEY="sk-emp-你的key"
```

**如果你电脑上开着代理 / 梯子**：Codex 会读取终端里的 `HTTPS_PROXY` 环境变量，请求会绕道代理——每次连接多花好几秒，还可能因为代理节点切换被风控当成"多个网络同时使用"。请把网关域名排除在代理之外（两种都做最稳）：

```bash
# 写进 ~/.zshrc 或 ~/.bashrc
export NO_PROXY="$NO_PROXY,.cloudwaveai.cn"
export no_proxy="$no_proxy,.cloudwaveai.cn"
```

并在代理软件的规则里把 `cloudwaveai.cn` 设为直连（DIRECT）。

之后照常使用 `codex` 即可。请求会经公司网关转发到你的专属账号。

## 三、其它客户端（Cursor / Cherry Studio 等）

**默认只允许官方 Codex 客户端**。第三方工具发来的请求会被网关拦截，返回 `client_not_allowed`，同时你会收到一条飞书提醒。

原因：第三方客户端的请求特征和官方客户端不同，容易让账号被 OpenAI 判定异常；另外，"只认 Codex"也让 Key 被拿去别的工具里转卖变得更难。

如果工作上确实需要第三方工具，请联系管理员。管理员放开后，"一键配置"页会给出对应的 Base URL 和填写方法。

## 四、查看用量和额度

- **我的用量**：今天 / 最近 7 天 / 30 天的请求数和 token 数，可按模型、按客户端查看。
- **账号额度**：你的账号 5 小时窗口和每周窗口的使用比例、恢复时间，以及账号当前状态。
- **我的日报**：每天早上系统会根据你前一天的使用，自动生成一份工作小结推送到飞书。

## 五、常见问题

- **返回"账号需要重新登录"**：你的上游账号 token 失效了，管理员已收到通知，稍等即可。
- **返回 429 / 限额**：账号命中了 5 小时或每周额度上限，页面会显示恢复时间；或同时并发太多（默认最多 4 个），稍后重试。
- **不要在对话里粘贴密码、密钥、私钥**：系统会尽力脱敏，但不保证覆盖所有情况，而且这些内容本就不该发给模型。
- **换电脑**：重新复制配置片段即可，Key 不用换。新电脑第一次使用时会收到"新设备"提醒，到"我的设备"点确认即可。
- **返回 `device_unconfirmed`**：这台设备还没确认，或者超过确认期限（默认 24 小时）。到"我的设备"确认后即可恢复。
- **返回 `device_blocked`**：这台设备被拉黑了（你点过"不是我"，或管理员操作）。只能由管理员恢复。
- **返回 `account_frozen`**：你的 Key 被冻结了，见下一节。
- **返回 `network_not_allowed`**：公司开启了"只允许在公司网络内使用"，你现在不在公司网络里。需要在外办公请找管理员开通远程使用。
- **返回 `content_blocked`**：你这条消息触发了公司的内容审核规则（例如要求写恶意软件、盗号工具、免杀程序）。这类请求会让 OpenAI 直接封掉账号，所以被拦下了。如果是误判，把原始需求发给管理员核实。
- **返回 `notice_required`**：使用说明更新了，登录门户重新确认一次即可。

## 六、设备确认与账号安全

你的 Key 只属于你一个人。为了防止 Key 被分享或转卖（外人用你的账号会让账号被 OpenAI 降智甚至封禁，公司也要替外人付费），网关会记录 Key 在哪些**设备**和**网络**上使用。

**新设备要确认。** Key 第一次在某台设备上使用时，你会收到飞书消息。打开门户的"我的设备"：

- 是你本人的设备：点 **确认是我**。
- 不是你：点 **不是我**。这台设备会被拉黑，你的 Key 会**立即作废**，请马上到"我的 Key"重新生成，并通知管理员。

没确认的设备可以先用 24 小时（管理员可调整），超时后会暂停，确认后恢复。

**什么情况会被冻结。** 下面两种情况几乎只会在 Key 被多人同时使用时出现，系统会自动冻结你的 Key：

1. 一台**没确认**的设备，和你的另一台设备在**不同网络**上几乎同时使用（新设备有 30 分钟宽限）；
2. 短时间内（默认 10 分钟）在 **3 个以上**不同网络同时使用。

冻结后你无法使用 Key，也不能自己重新生成，**只能由管理员核实后解冻**。如果你认为是误判，直接联系管理员说明情况即可。

**内容审核。** 每个请求发给 OpenAI 之前，网关会用规则检查你最新的一条消息，只看这一条，不看历史对话和工具输出。命中"写勒索软件、盗号、免杀、发起 DDoS"这类网络滥用规则时，管理员会收到提醒；如果公司设成了拦截模式，这条请求会被直接拒绝。正常的安全开发工作（修漏洞、写单元测试、做加固）不在规则范围内。

**避免误判的建议：**

- 及时确认自己的新设备。
- 不要用会自动切换节点的代理 / VPN 访问网关，把网关域名设为**直连**。节点频繁切换会被看成"好几个地方同时在用"。
- 办公室和家里各一台电脑没问题，只要都确认过，同时用也不会冻结。
