# 合规与告知说明

本文档给管理者和法务参考，说明本系统在合规上的立场与需要配套的动作。**不是法律意见**，落地前请咨询公司法务。

## 1. 与 OpenAI 服务条款的关系

已核对 OpenAI Codex 负责人 Thibault Sottiaux 的公开表态：

- 2026-05-23：可以在其它工具里用 ChatGPT 账号登录使用（官方与开源客户端均可）。
- 2026-08-21：把订阅转成 API 流量再转供他人、或多人共享一个账号，不受支持，会被反欺诈系统标记。

**本系统的定位**：严格一人一号，员工拿到的是绑定到本人专属账号的内部 Key，网关不做号池、不跨账号共享。这不属于"多人共享一个账号"。但"订阅经网关以 API 形式使用"仍属于灰色地带，存在被 OpenAI 判定异常的**剩余风险**。

**为降低风险，本系统采取的措施**：

1. 一个员工 = 一个付费账号，绑定关系固定、可审计。
2. 每个账号固定一个海外出口 IP（分组），不漂移。
3. 员工自助页默认推荐官方 Codex 客户端配置；第三方客户端（Cursor、Cherry Studio 等）风险更高，在后台单独标记。
4. 每账号并发上限（默认 4），避免异常并发。
5. 账号健康监测：出现"降智"（响应模型与请求不符、推理量被封顶）等信号时告警。
6. **不伪造 TLS 指纹**去冒充官方客户端二进制——保持"一人一真实付费账号"的立场，而非规避检测。
7. **防止员工把 Key 分享或转卖**：默认只允许官方 Codex 客户端；登记每个 Key 使用的设备和网络；第一台设备自动信任，之后的新设备需员工本人确认；同一 Key 在不同网络同时使用时自动冻结，只有管理员能解冻。这一条直接对应 OpenAI 反对的"多人共享一个账号"，是一人一号承诺能否兑现的关键。

**明确不做**：不把一个账号分给多人；不做转售；不隐藏真实使用形态。

## 2. 与 Anthropic 的关系（为什么第一期不接 Claude）

Anthropic 的条款明确禁止第三方开发者代表用户中转 Free/Pro/Max 计划的凭证，也禁止收集、存储或中介 claude.ai 的 token；自 2026-01-09 起有服务端封堵。因此本系统**不接入 Claude 订阅**。员工若需 Claude，应走 API Key 或 Team 套餐等官方许可的方式。

## 3. 员工数据与日志（中国《个人信息保护法》相关）

本系统会完整记录员工经网关发出的请求与模型回复，用于账号安全和问题排查。这涉及员工个人信息处理，需配套：

1. **告知**：订阅由公司提供，记录的数据归公司所有。门户里不设告知弹窗或说明页；由公司按需通过正常渠道（IT 使用制度、入职资料等）告知员工。
2. **最小化与目的限定**：日志仅用于账号安全和问题排查，不得用于无关目的。
3. **访问控制**：员工只能看自己的使用日志（不含对话内容）；超级管理员可看全部，每次查看原文都写入不可篡改的审计表；部门负责人只能看到团队总用量和成员账号是否正常，看不到对话和个人用量。AI 周报只发给员工本人，员工可以自己关掉。
4. **存放位置**：支持把数据库和对话原文（对象存储）放在国内，服务本身在海外（见 `docs/rollout.md`）。注意请求内容仍要发往 OpenAI，出境这一环依然存在。
5. **保留期限**：对话原文默认保留 180 天后自动删除；用量统计与周报可长期保留（不含敏感原文）。
6. **脱敏**：原文落库前对常见密钥/私钥/连接串做正则脱敏。**正则无法覆盖所有情况**，这一点在后台明确提示，不能替代员工自身不在对话中粘贴敏感凭证的注意义务。
7. **安全**：代理地址等敏感配置加密存储；数据库磁盘应开启加密；定期备份并演练恢复。
8. **设备与 IP 记录（防 Key 外泄）**：为发现 Key 被分享或转卖，系统会记录每次请求的来源 IP，以及设备标识（Codex 安装 ID，或客户端 User-Agent 的摘要）。可选的离线 IP 库只把 IP 解析到省市和运营商，不调用任何外部服务。这些数据：
   - 目的仅限账号安全，不用于考勤、定位或绩效；
   - 员工本人可以在"我的设备"里看到自己的设备；网络记录只有管理员在风险中心可见；
   - 冻结、解冻、拉黑、确认等操作都写审计。

9. **内容审核**：请求发给 OpenAI 之前，网关用规则检查员工最新的一条消息，目的是避免因网络滥用被 OpenAI 封号。命中时只记录规则名和前后约 40 个字的片段，管理员可见；是否拦截由公司在设置里决定。这属于前面"请求会被记录"范围内的处理，但建议在 IT 制度里写明"禁止用于编写恶意软件、攻击工具等"。
10. **公司网络限制（可选）**：开启后 Key 只能在公司网络内使用，这是防止 Key 外泄最直接的手段；需要远程办公的员工单独放开并留审计。

## 4. 需要公司决策/法务确认的点

- [ ] 是否通过公司正常渠道（IT 使用制度、入职资料等）告知员工对话会被记录。
- [ ] 是否需要为"记录员工对话"单独出具书面同意书。
- [ ] 原文 180 天保留期是否符合公司数据留存与合规要求。
- [ ] 超级管理员可查看员工对话原文（每次留审计），是否符合公司管理授权范围。
- [ ] 接受"订阅经网关使用"对 OpenAI 而言的剩余合规风险。
- [ ] 公司制度中写明"禁止分享、转卖 Key"及违规处理办法。
- [ ] 记录员工设备标识和来源 IP 用于账号安全，是否需要在员工手册中单独说明。
- [ ] 内容审核用"仅提醒"还是"拦截"；IT 制度中是否明确禁止用公司 AI 编写恶意软件、攻击工具。
- [ ] 是否开启"只允许在公司网络内使用"，以及哪些人可以远程使用。
- [ ] 自动冻结可能误伤（例如员工的代理频繁切换节点），确认由谁负责核实和解冻、响应时限多长。
