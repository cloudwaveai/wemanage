# 合规与告知说明

本文档给管理者和法务参考，说明本系统在合规上的立场与需要配套的动作。**不是法律意见**，落地前请咨询公司法务。

## 1. 与 OpenAI 服务条款的关系

已核对 OpenAI Codex 负责人 Thibault Sottiaux 的公开表态：

- 2026-05-23：可以在其它工具里用 ChatGPT 账号登录使用（官方与开源客户端均可）。
- 2026-08-21：把订阅转成 API 流量再转供他人、或多人共享一个账号，不受支持，会被反欺诈系统标记。

**本系统的定位**：严格一人一号，员工拿到的是绑定到本人专属账号的内部 Key，网关不做号池、不跨账号共享。这不属于"多人共享一个账号"。但"订阅经网关以 API 形式使用"仍属于灰色地带，存在被 OpenAI 判定异常的**剩余风险**。

**为降低风险，本系统采取的措施**：

1. 一个员工 = 一个付费账号，绑定关系固定、可审计。
2. 每个账号固定一个海外出口 IP（分组），不漂移。
3. 员工自助页默认推荐官方 Codex 客户端配置；第三方客户端（Cursor、Cherry Studio 等）风险更高，在后台单独标记。
4. 每账号并发上限（默认 4），避免异常并发。
5. 账号健康监测：出现"降智"（响应模型与请求不符、推理量被封顶）等信号时告警。
6. **不伪造 TLS 指纹**去冒充官方客户端二进制——保持"一人一真实付费账号"的立场，而非规避检测。
7. **防止员工把 Key 分享或转卖**：默认只允许官方 Codex 客户端；登记每个 Key 使用的设备和网络；新设备需员工本人确认；同一 Key 在不同网络同时使用时自动冻结，只有管理员能解冻。这一条直接对应 OpenAI 反对的"多人共享一个账号"，是一人一号承诺能否兑现的关键。

**明确不做**：不把一个账号分给多人；不做转售；不隐藏真实使用形态。

## 2. 与 Anthropic 的关系（为什么第一期不接 Claude）

Anthropic 的条款明确禁止第三方开发者代表用户中转 Free/Pro/Max 计划的凭证，也禁止收集、存储或中介 claude.ai 的 token；自 2026-01-09 起有服务端封堵。因此本系统**不接入 Claude 订阅**。员工若需 Claude，应走 API Key 或 Team 套餐等官方许可的方式。

## 3. 员工数据与日志（中国《个人信息保护法》相关）

本系统会完整记录员工经网关发出的请求与模型回复，用于用量管理和工作分析。这涉及员工个人信息处理，需配套：

1. **事先告知并取得同意**：员工首次登录自助页时展示告知文案，必须点击"我已知晓"方可获取 Key，点击时间入库留痕。**建议同时把这条写进公司 IT 使用制度/员工手册，并让员工书面确认。**
2. **最小化与目的限定**：日志仅用于用量与工作情况管理，不得用于无关目的。
3. **访问控制**：超级管理员可看全部；部门负责人仅可看本部门；每次查看他人原文都写入不可篡改的审计表。
4. **保留期限**：对话原文默认保留 180 天后自动删除；用量统计与日报可长期保留（不含敏感原文）。
5. **脱敏**：原文落库前对常见密钥/私钥/连接串做正则脱敏。**正则无法覆盖所有情况**，这一点在后台明确提示，不能替代员工自身不在对话中粘贴敏感凭证的注意义务。
6. **安全**：代理地址等敏感配置加密存储；数据库磁盘应开启加密；定期备份并演练恢复。
7. **设备与 IP 记录（防 Key 外泄）**：为发现 Key 被分享或转卖，系统会记录每次请求的来源 IP，以及设备标识（Codex 安装 ID，或客户端 User-Agent 的摘要）。可选的离线 IP 库只把 IP 解析到省市和运营商，不调用任何外部服务。这些数据：
   - 目的仅限账号安全，不用于考勤、定位或绩效；
   - 员工本人可以在"我的设备"里看到自己的全部设备和网络记录；
   - 冻结、解冻、拉黑、确认等操作都写审计；
   - 已在告知文案中写明（告知版本 2），员工需重新确认。

## 4. 告知文案（默认，版本 2）

> 本服务的请求和回复会被公司记录，用于用量管理和工作分析，原文保留 180 天。为保障账号安全，还会记录你使用的设备和来源 IP。请勿把 Key 分享给他人，分享或转卖将按公司制度处理。继续使用即表示你已知晓。

告知带版本号。在后台"设置"里修改文案后，版本号自动加 1，**所有员工**（包括已确认过旧版本的）都要重新确认才能继续使用 Key，每次确认的时间和版本都会留痕。

升级到本版本时，已确认过旧文案（版本 1，不含设备和 IP 条款）的员工会被要求重新确认一次。
