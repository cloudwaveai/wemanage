# 项目归整、知识审核与 Skill 流程预览

本次只改 We-Manage 服务与静态界面，网关无变更。

## 使用流程

1. 项目 → 自动归整项目，或知识库 → 知识审核。
2. 自动整理读取现有日报/周报提取的全部可见项目线索，使用 gpt-6.1-sol 生成归并与知识建议。
3. 查看新增、重复、需更新、冲突、证据不足，逐项核对引文和项目来源。
4. 归并由管理员确认；知识保存为草稿，再从专家审核分配审核人。
5. Skill 展示条件流程图和完整原文。既有组织资产支持修改新版本、撤回与恢复，保留历史。

## 范围和限制

- 这是对已有提取线索的整理，不是新一轮全量原始日志分析。证据不足回到对应项目深入整理。
- 首版由页面按钮或运维命令启动，未新设每日定时任务。
- 归并必须有两个项目各自的引文；相似名称不自动合并。
- 新建、更新与冲突分类来自提取线索之间的比较，不代表已与全部历史已发布资产作语义对照。
- 已有同来源、同类型资产不会覆盖；管理员到资产页核对并编辑新版本。
- 完整输入超过 1.5 MB 会明确拒绝，不静默截断材料；模型未覆盖所有输入线索或引文、流程校验失败，结果标为失败，保留模型原始输出供排查。
- 所有模型输入线索都关联到派生资产，采用保守隔离：任一输入后续私密/隐藏，相关整理结果及资产不可见。
- 不推断费用、人员绩效、负责人或未有依据的商业日期；无自动执行 Skill 能力。
- 本轮借鉴 Graphiti 的实体判断规则和 Hermes 的来源、版本与归档机制，使用现有 Go/PostgreSQL 实现；没有宣称安装这两个框架，也没有新增图数据库。

## 验证

- Go 测试覆盖完整工作流、重复调用复用、草稿保存幂等、非管理员隔离、私密来源隐藏、伪造引文、缺失输入覆盖、错误流程与循环归并。
- 浏览器本地样例检查：流程图、保存草稿、证据不足不可直接保存资产、暂不沉淀、390px 布局和脚本错误。
- 运维：`wemanage curate <管理员员工 ID>` 使用既有模型配置，校验管理员资格，不创建登录会话。
- 部署前检查活跃总结和整理任务；仅增加 wm_ 表，保留上一版二进制回滚路径，不复制生产库。
