日期：2026-11-04。范围：独立 We-Manage。本文是设计交付；标注“后续”的能力尚未上线。

目标

让管理者理解一个人正在承担什么工作、解决什么问题、形成什么方法，以及有哪些能跨时间比较的成长线索。每项判断应能回到来源，不依据 Token、调用量或在线时间推断绩效。

页面实现形式

顶部仅保留姓名、部门、日期选择；第一屏展示工作概览、项目和待核对问题。方法与成长放在第二层，用量独立分组。每条线索可展开依据。未接入的岗位、Exam 不填假值，也不画零分雷达图。必要说明集中放入“数据范围”，避免每块重复。

当前模型结果为文字草稿。下一步可将事实项拆为稳定编号，增加人工纠正和历史版本：内容、来源编号、来源日期、判断状态、核对人、核对时间。事实纠正不覆盖原始日志。

实施顺序与验收

1. 先用现有日报形成一人的跨日工作画像，逐项核对来源，确认无其他人员私密内容混入。

2. 接入岗位表时使用稳定员工 ID；无法映射的行保留待处理，不按姓名直接覆盖。

3. Exam 数据单独建表，记录试卷及评分版本；只有同口径结果允许趋势比较。

4. 最后增加人工修正与共享范围；当前入口仍限有效超级管理员，不能将此文档视为已上线全员共享。

通过标准：核心事实均有来源；未完成与建议不混写成成果；日期范围可解释；缺失数据不推断为未工作；私密人员在读取、生成和历史展示三个环节均排除。业务验收由负责人填写。

产品目标

将分散工作记录整理成连续项目脉络，再将有证据、有适用条件的做法沉淀为组织知识与 Skill。先从已有日报快速定位高价值材料，需要核实时再读取对应人员和日期的日志。

这里的回路依靠新工作记录中可追溯的引用积累证据，不建设使用者反馈问卷，也不要求员工填反馈表。

知识卡片应包含什么

标题、所属项目、问题场景、方法、实际结果、适用条件、不适用情况、验证步骤、来源及日期、状态、版本、负责人。模型原文与人工修改版本分别保留。隐藏和撤回只改变展示状态，不清除正式来源。

Skill 的可审核预览按“何时使用 → 准备什么 → 怎么做 → 分支条件 → 如何验证 → 何时停止”展示。现有流程预览已支持场景、步骤、验证和限制；后续增加明确分支与版本差异，缺失步骤保持待补充。

自动整理与快速路径

继续复用现有日报、周报提取任务。项目进展第一版按需生成：使用项目候选引用的日报快照，最多 31 天；来源过大或存在冲突版本时停止并提示，不截断。没有被提取到的项目线索不会自动进入此项目分析，所以不能称为全量项目覆盖。

后续增量任务以“来源版本 + 项目 + 分析规则版本”为去重键，只处理新增或变化的材料；不要为每次打开页面重复跑模型。日汇总解决当日发生什么，周汇总串联阶段变化，月度检查知识是否仍适用。

共享与权限

当前服务仅管理员可用。未来共享至少区分私密、项目内、组织内三个范围；先过滤来源权限再检索，生成结果继承最严格的来源范围。来源权限收紧时，搜索结果、历史分析、资产版本及导出入口都要同步隐藏。老板的私密内容维持排除，不因整理成为知识而公开。

当前尚无全员知识发布能力。新增成员访问前，必须单独实现角色与来源权限校验，不能只开放现有管理员接口。

组织资产整合

先按人员、项目和来源日期关联现有资产；再接入经指定的飞书知识库目录。先保存文档引用及权限，不全量复制无关文档。项目知识与通用知识分开，跨项目复用需核对是否含客户专属信息。

项目上下文手册

每个项目应汇集目标与范围、当前阶段、关键决定、相关人员、文档与仓库入口、约束、常见问题、可复用 Skill。每条事实关联来源和日期。模型推导的项目归属、负责人及阶段先作为候选，允许人工修改、归并或隐藏。缺少证据就显示待确认，不凭请求量推定岗位或责任。

手册保存事实版本与引用；更新时区分新增事实、已改变事实、冲突和已失效做法。不同日期的决定应串联演变过程，不能只用最新摘要覆盖历史。来源收紧权限后，手册和派生资产同步收紧展示范围。

从经验到可执行 Skill

审核对象应是完整方法：触发场景、输入材料、权限前提、步骤、分支、验证、停止条件及人工确认点。流程图与文字共用一份结构化内容，避免图与实际步骤不一致。缺少验证证据的经验可保存为候选，但不能标记为已验证 Skill。

后续选择一个重复出现且证据完整的问题，贯通“日报发现 → 日志核实 → Skill 草稿 → 流程预览 → 人工审核 → 新工作引用”。验收看是否能沿来源复查、按步骤完成并验证结果；不以知识卡数量作为效果证明。

本阶段取舍

优先完善项目上下文、可审核 Skill 和待决策草稿。跨仓库自动执行、自动开发、机器人发消息以及自动部署不属于本轮实现。继续不做使用者反馈问卷。老板私密来源持续排除，文章中的 Session 共享做法不构成开放权限的授权。

人员画像侧重做过什么、承担哪些有证据的工作、使用什么方法、成果是否验证，以及方法如何变化。文章中的费用和团队效率属于作者自述，不作为我方预算目标或个人绩效标准。
